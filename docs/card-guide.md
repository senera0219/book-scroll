# 카드 제작 가이드

- 버전: 0.1 (2026-11-12). 시험 제작 5권을 만든 뒤 고친다(`docs/DECISIONS.md` Q-1, Q-2).
- 누가 읽나: 카드를 만들거나 검수하는 **모든 AI(Claude, ChatGPT 등)와 사람**. 어느 AI가 만들어도 같은 결과가 나오게 하는 것이 목적이다.
- JSON 모양(필드 이름·구조)의 정본은 `docs/ARCHITECTURE.md` §4다. 이 문서는 **각 필드를 어떻게 채우는지**를 정한다. 둘이 다르면 §4가 맞고, 이 문서를 고친다.
- 다른 AI에게 맡길 때는 이 파일 전체와 `docs/ARCHITECTURE.md` §4를 함께 붙여넣는다.

---

## 1. 이 서비스와 카드

쇼츠처럼 세로로 넘기면 다른 책이, 가로로 넘기면 같은 책의 다음 카드가 나온다. 마지막에는 **해설 카드**가 나오고, 진짜 책(구매·도서관)으로 이어진다. 카드는 **책의 입구이지 책의 대체가 아니다.** 책 전체를 옮기지 않는다.

## 2. 절대 규칙

1. **사실은 원문에서만.** 카드(`cards`)의 내용은 `pipeline/sources/`에 저장한 원문에 근거가 있어야 한다. 원문에 없는 사건·숫자·인용·인물을 만들지 않는다.
2. **저작권이 끝난 글만.** 원문은 퍼블릭 도메인이어야 한다. 외국 고전은 **번역본(영역본)도 저작권이 끝난 것**만 쓴다(예: 19세기 영역본). 최근 번역본은 쓰지 않는다.
3. **모르면 비운다.** 확실하지 않은 정보는 쓰지 않고 검수 기록(§8)의 "확인 필요"에 적는다. 그럴듯하게 채우는 것보다 비어 있는 것이 낫다.
4. **만든 AI와 검수하는 AI는 다르다.** 같은 AI는 자기 실수를 놓친다.
5. **링크는 직접 열어 본 것만.** `source.url`, `commentary.links`의 주소는 실제로 열리는지 확인한다.

## 3. 만드는 순서

| 단계 | 하는 일 | 결과물 |
|---|---|---|
| 1. 원문 받기 | 원본 사이트에서 원문을 받고, 저작권 상태를 사이트에서 다시 확인 | `pipeline/sources/<책id>.txt` |
| 2. 범위 고르기 | 카드로 만들 부분(짧은 묶음 3~5장 또는 한 챕터)을 고른다 | 검수 기록에 "고른 범위" |
| 3. 번역 | 외국어면 한국어로 번역(§6) | — |
| 4. 카드 만들기 | 형식(§4)과 길이(§5)에 맞춰 `cards` 작성 | `content/books/<책id>.json` |
| 5. 해설 카드 | `commentary`, `dailyQuote` 작성(§7) | 같은 파일 |
| 6. 자가 점검 | §9 체크리스트 | — |
| 7. 다른 AI 검수 | 원문과 대조해 검수 기록 작성(§8) | `pipeline/reports/<책id>.md` |
| 8. 반영 | 지적을 고치고 `review` 필드 채우기, `content/index.json`에 책 추가 | — |

원문 파일 맨 위에는 다음 세 줄을 둔다.

```
출처: <원문 페이지 주소>
받은 날짜: YYYY-MM-DD
판본: <예: George Long 영역본 (Project Gutenberg #15877) — 번역자 이름까지>
```

## 4. 카드 형식 (`type`)

네 가지를 모두 쓸 수 있다. 무엇을 주로 쓸지는 시험 제작 뒤에 정한다. **한 책 안에서는 한두 가지 형식만** 쓴다.

| type | 언제 | 쓰는 법 | 하면 안 되는 것 |
|---|---|---|---|
| `quote` | 짧은 단상·명언이 많은 책 (명상록) | `text`에 한 문장~짧은 단락, `note`에 2~3줄 해설 | 원문에 없는 뜻을 해설에 덧붙이기 |
| `summary` | 설명형·논증형 글 (촛불의 과학, 군주론) | 한 카드에 생각 하나. 원문의 순서와 논리를 따라 쉬운 말로 다시 쓴다 | 원문에 없는 예시·숫자·결론 |
| `excerpt` | 문장 자체가 좋은 대목 | 원문(또는 번역문) 한 단락을 그대로. 앞뒤를 자르면 `…` 표시 | 여러 곳을 이어 붙여 한 단락처럼 보이게 하기 |
| `original` | 한국어 원문 소설·수필 (운수 좋은 날) | 원문을 순서대로 이어서 나눈다. 넘겨 읽는 맛이 목적 | 문장 고치기·줄이기 |

`note`는 `type`이 `quote`일 때만 쓴다.

## 5. 길이

휴대폰 한 화면(기본 글자 크기)에 다 들어와야 한다. 넘치면 줄이지 말고 **카드를 둘로 나눈다.** 나눌 때는 문장 중간에서 끊지 않는다.

| 항목 | 기준(공백 포함, 잠정) |
|---|---|
| `quote`의 `text` | 120자 이내 |
| `note` | 2~3문장, 150자 이내 |
| `summary`의 `text` | 300자 이내 |
| `excerpt`·`original`의 `text` | 400자 이내 |
| 한 책의 카드 수 | 짧은 묶음이면 3~5장, 챕터면 챕터 길이만큼(해설 카드 제외) |
| `commentary.about`·`today` | 각 300자 이내 |
| `dailyQuote` | 60자 이내 |

숫자는 첫 화면을 만든 뒤(`#5`) 실제 휴대폰에서 보고 고친다.

## 6. 번역과 말투

- **번역 기준:** 판본에 적은 그 번역본(예: 영역본)에서 한국어로 옮긴다. 다른 번역본이나 기억에 있는 한국어 번역을 섞지 않는다.
- **뜻을 먼저, 말은 자연스럽게.** 직역투(“그것은 ~이다”, “~하는 것이 가능하다”)를 피하고 오늘의 한국어로 쓴다. 단, 문장을 빼거나 뜻을 더하지 않는다.
- **말투:** 본문(`text`)은 원문의 분위기를 살린 평서체(“~다”). 해설(`note`, `commentary`)도 평서체로 통일한다.
- **고유명사:** 국립국어원 외래어 표기법을 따른다. 처음 나올 때 필요하면 괄호에 원어를 한 번 적는다.
- **한국어 원문(`original`):** 단어·문장·사투리·순서는 그대로 둔다. 읽기 어려운 옛 맞춤법(띄어쓰기, 아래아 등)만 현대 표기로 바꾸고, 바꾼 원칙을 검수 기록에 적는다.

## 7. 해설 카드와 나머지 필드

- `commentary.about` — 이 책이 어떤 책인지: 누가, 언제, 왜 썼는지와 핵심 한 가지.
- `commentary.today` — 그리고 지금은: 오늘의 삶과 어떻게 이어지는지. 오래된 과학·정치 내용이면 "지금은 이렇게 밝혀졌다"를 쓴다.
  - 해설 카드는 원문 밖의 사실(저자의 생애, 이후의 연구)을 쓸 수 있는 **유일한 곳**이다. 단, 널리 확인된 사실만 쓰고, 확실하지 않은 연도·숫자는 빼며, 무엇을 근거로 했는지 검수 기록에 적는다.
- `commentary.related` — 이 서비스에 있는(또는 넣을 예정인) 다른 책의 `id`. 억지로 채우지 않는다. 없으면 `[]`.
- `commentary.links` — `buy`는 온라인 서점에서 책 제목으로 검색한 결과 페이지, `library`는 도서관 검색 결과 페이지. 직접 열어 본 주소만 쓴다.
- `dailyQuote` — 이 책 `cards` 안의 문장에서 고른다. 새로 지어내지 않는다.
- `id` — 책 id는 영어 소문자와 `-`만(예: `meditations`, `lucky-day`). 카드 id는 `<책id>-01`, `-02`…처럼 두 자리 번호. 한 번 정한 id는 바꾸지 않는다(읽은 기록이 id로 저장된다).
- `tab` — `literature`(문학) · `self-help`(자기계발) · `philosophy`(철학) · `society`(사회·정치) · `science`(과학·기술) 중 하나.
- `source` — `originalLang`은 원래 언어 코드(그리스어 `grc`, 라틴어 `la`, 영어 `en`, 한국어 `ko` 등). `translatedFrom`은 실제로 옮긴 번역본의 언어. 한국어 원문이면 `null`. `license`는 지금은 `"public-domain"`만 쓴다. `url`은 책 전체 페이지가 아니라 **받은 그 판본의 페이지**.
- `review` — 검수가 끝난 뒤에만 채운다. `generatedBy`·`reviewedBy`는 `claude`·`chatgpt`처럼 소문자, `date`는 검수 기록의 날짜.

## 8. 검수 기록 (`pipeline/reports/<책id>.md`)

검수하는 AI는 **원문 파일과 카드 JSON을 나란히 놓고** 카드마다 대조한다. 아래 모양으로 쓴다.

```markdown
# <책 제목> 검수 기록
- 날짜: YYYY-MM-DD
- 만든 AI: claude / 검수한 AI: chatgpt
- 원문: pipeline/sources/<책id>.txt (판본: …)
- 고른 범위: <예: 2권 1~4절>

| 카드 id | 원문 위치 | 판정 | 지적 |
|---|---|---|---|
| meditations-01 | 2권 1절 | 통과 | — |
| meditations-02 | 2권 4절 | 수정 | "언제나"는 원문에 없음 → 삭제 |

## 해설 카드
- about: 통과 / 근거: …
- today: 수정 / 근거: …

## 확인 필요
- <확실하지 않아 사람이 확인해야 하는 것>

## 반영
- <만든 AI가 무엇을 고쳤는지. 다 고친 뒤 작성>
```

**판정 기준**

| 판정 | 뜻 |
|---|---|
| 통과 | 원문과 뜻이 같고, 빠지거나 더한 내용이 없다 |
| 수정 | 고치면 쓸 수 있다(낱말, 뉘앙스, 길이) |
| 삭제 | 원문에 근거가 없거나 뜻이 틀렸다 |

**검수할 때 보는 것**

1. 원문에 없는 내용(사실·숫자·인용·감정)이 들어갔나
2. 원문의 뜻을 뒤집거나 과장했나(“때로” → “언제나”)
3. 번역에서 빠진 문장이 있나
4. `excerpt`·`original`이 원문 그대로인가
5. 길이(§5)와 형식(§4)을 지켰나
6. 해설 카드의 원문 밖 사실이 널리 확인된 것인가

## 9. 자가 점검 (만든 AI가 검수 전에)

- [ ] 모든 카드의 원문 위치를 댈 수 있다
- [ ] `source.url`을 열어 보았고 판본이 맞다
- [ ] 길이 기준을 넘는 카드가 없다
- [ ] `quote`가 아닌 카드에 `note`가 없다
- [ ] `dailyQuote`가 `cards` 안의 문장이다
- [ ] 카드 id가 `<책id>-01`부터 빠짐없이 이어진다
- [ ] JSON 문법이 맞다(검사 도구는 `#4`에서 만든다)

## 10. 예시

**좋은 예 — `quote` (명상록, George Long 영역본(Gutenberg #15877) 2권 1절에서 번역)**

원문(영역본): "Begin the morning by saying to thyself, I shall meet with the busybody, the ungrateful, arrogant, deceitful, envious, unsocial. All these things happen to them by reason of their ignorance of what is good and evil."

```json
{
  "id": "meditations-01",
  "type": "quote",
  "text": "아침을 시작하며 스스로에게 말하라. 오늘 나는 참견하기 좋아하는 사람, 고마워할 줄 모르는 사람, 오만한 사람, 남을 속이는 사람, 시기하는 사람, 어울릴 줄 모르는 사람을 만날 것이다.",
  "note": "하루를 시작하기 전에 마주칠 사람들을 미리 떠올려 둔다. 바로 이어서 그는 그들이 그렇게 행동하는 것은 무엇이 선이고 무엇이 악인지 모르기 때문이라고 말한다."
}
```

`text`는 104자, `note`는 88자로 기준 안이다. 한 문장이 기준을 넘으면 끊지 말고 한 카드로 두되, 검수 기록의 "지적"에 예외라고 적는다. `note`에는 원문 밖 사실(예: "로마 황제가 쓴 메모")을 넣지 않았다. 그런 내용은 해설 카드에 쓴다.

**좋은 예 — `original` (운수 좋은 날 첫 문장, 위키문헌 https://ko.wikisource.org/wiki/운수_좋은_날)**

```json
{
  "id": "lucky-day-01",
  "type": "original",
  "text": "새침하게 흐린 품이 눈이 올 듯하더니 눈은 아니 오고 얼다가 만 비가 추적추적 내리었다."
}
```

기억에 의존하면 "내리는 날이었다"처럼 원문과 다르게 쓰기 쉽다. `original`·`excerpt`는 반드시 원문 파일에서 복사한다.

**나쁜 예**

| 카드 | 왜 안 되나 |
|---|---|
| `"text": "마르쿠스는 매일 새벽 4시에 일어나 이 글을 썼다."` | 원문에 없는 사실 |
| `"note": "현대 심리학에서도 이 방법이 스트레스를 40% 줄인다고 밝혀졌다."` | 원문 밖 사실 + 확인 안 된 숫자. 해설 카드에도 쓰면 안 된다 |
| `"type": "summary"`, `"note": "…"` | `note`는 `quote`일 때만 |
| `excerpt`에 2권 1절과 5절을 이어 붙임 | 한 단락처럼 보이게 이어 붙이면 안 된다 |

## 11. 이 문서를 고칠 때

- 형식·길이·말투가 바뀌면 버전과 날짜를 올리고, 되돌리기 어려운 결정은 `docs/DECISIONS.md`에 `D-n`으로 남긴다.
- JSON 필드를 더하거나 바꾸면 먼저 `docs/ARCHITECTURE.md` §4를 고친다.
